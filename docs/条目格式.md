# NyaPassword 条目格式 1.0

> 对应 `npw-model`（common 仓库 `crates/npw-model`），`FORMAT_MAJOR = 1`、`FORMAT_MINOR = 0`、`FORMAT_VERSION = "1.0"`。本文描述**代码实际的行为**；与 [设计方案.md](设计方案.md) §5 有出入时以本文为准。
> 冻结的 JSON Schema：`crates/npw-model/format/history/v1.0/schema.json`；加密兼容样例：`crates/npw-core/tests/compat/v1.0/vectors.json`（§8）。

一个**条目**的一个**修订**是一份 UTF-8 JSON，整体用条目密钥 IK 加密（[加密规格.md](加密规格.md) §4–§6），服务端只看到密文。加密以条目为单位，合并以字段为单位（§7）。

## 0. 总则

- 只有核心（`npw-model`，经 `npw-core` / WASM / UniFFI）读写条目 JSON，各端界面拿到的是核心解析好的结构，写回时也交给核心。
- 时间一律是 UTC 毫秒整数。文本原样保存，不改换行符，不做 Unicode 规范化。
- 二进制值（passkey 的凭据 ID、私钥，附件密钥）用 base64url 无填充。
- 每个对象都**保留不认识的键**（§5）。
- 序列化用 `serde_json`（`preserve_order`）：键按下文表格的顺序输出，不认识的键排在最后、保持读入时的顺序；值为默认值的可省略键不输出。内容哈希对密文计算，不依赖 JSON 的字节形式。
- 条目 ID 是客户端生成的 UUIDv7（`npw_model::new_id`），只出现在服务端元数据和 AAD 里，不在条目 JSON 里。

## 1. 顶层（`ItemContent`）

```json
{
  "format": "1.0",
  "template": "login",
  "title": "GitHub",
  "favorite": true,
  "reprompt": true,
  "tags": ["工作/开发"],
  "fields": [
    { "id": "username", "label": "用户名", "kind": "text", "purpose": "username", "value": "octocat" },
    { "id": "password", "label": "密码", "kind": "concealed", "purpose": "password", "value": "…" },
    { "id": "otp", "label": "一次性密码", "kind": "totp", "purpose": "otp", "value": "otpauth://totp/GitHub:octocat?secret=…" },
    { "id": "f_7c1e2a9b04d3", "label": "恢复码", "kind": "concealed", "value": "aaaa-bbbb\ncccc-dddd", "section": "s_0f3a5c7e9b21", "multiline": true }
  ],
  "sections": [{ "id": "s_0f3a5c7e9b21", "label": "恢复" }],
  "urls": [
    { "id": "u_4b6d8f0a2c4e", "url": "https://github.com/login", "match": "domain" },
    { "id": "u_9e1c3a5b7d9f", "url": "androidapp://com.github.android", "match": "exact", "cert_sha256": ["<hex>"] }
  ],
  "passkeys": [
    { "id": "pk_…", "rp_id": "github.com", "credential_id": "…", "user_handle": "…", "user_name": "octocat",
      "alg": -7, "private_key": "<PKCS#8 DER, base64url>", "counter": 0, "discoverable": true, "created_at": 1759536000000 }
  ],
  "notes": "",
  "attachments": [
    { "id": "<UUID>", "name": "recovery.txt", "size": 1234, "mime": "text/plain", "key": "<32 字节, base64url>",
      "blob_sha256": "<hex>", "created_at": 1759536000000 }
  ],
  "history": [{ "id": "h_…", "field": "password", "label": "密码", "value": "旧密码", "until": 1759536000000 }],
  "created_at": 1759536000000,
  "updated_at": 1759536000000
}
```

| 键 | 类型 | 缺省 / 何时省略 | 说明 |
|---|---|---|---|
| `format` | 字符串 `MAJOR.MINOR` | **必需** | §6 |
| `template` | 字符串 | **必需** | 内置模板 ID（§4）或更新客户端的模板；不认识的模板照常显示和编辑 |
| `title` | 字符串 | 缺省 `""`；总是输出 | |
| `favorite` | 布尔 | `false` 时省略 | 收藏 |
| `archived` | 布尔 | `false` 时省略 | 归档（列表默认不显示，安全检查不计入；仍参与自动填充建议） |
| `reprompt` | 布尔 | `false` 时省略 | 使用前需要验证（相当于 Bitwarden 的“主密码重新提示”）：显示、复制、填写这个条目的秘密前，各端先要用户再次验证（主密码，或 Windows Hello / 指纹）。只是界面和流程上的防护，条目的加密方式不变（[威胁模型.md](威胁模型.md) §3.8.1）。1.0 发布前加入 |
| `tags` | 字符串数组 | 空时省略 | 嵌套标签用 `/` 分隔，如 `工作/开发` |
| `fields` | Field 数组 | 缺省 `[]`；总是输出 | §2 |
| `sections` | Section 数组 | 空时省略 | `{id, label}`；字段用 `section` 引用 |
| `urls` | UrlEntry 数组 | 空时省略 | §3.1 |
| `passkeys` | Passkey 数组 | 空时省略 | §3.2 |
| `notes` | 字符串 | 空时省略 | 备注（合并时按行三方合并） |
| `attachments` | Attachment 数组 | 空时省略 | §3.3 |
| `history` | HistoryEntry 数组 | 空时省略 | 密文字段的旧值（§3.4） |
| `autofill` | 对象 | 全为默认时省略 | `auto_submit`（填完自动提交）、`never`（不自动填充），都是 `false` 时省略 |
| `ssh` | 对象 | 无时省略 | SSH agent 设置：`confirm_each_use`（缺省 `true`，每次签名都确认）、`git_signing`（`false` 时省略）。`ssh_key` 模板的新条目自带 `{"confirm_each_use": true}` |
| `conflicts` | Conflict 数组 | 空时省略 | 同步冲突中没被采用的值（§3.5） |
| `created_at` / `updated_at` | 整数 | 缺省 0；总是输出 | `updated_at` 保存时至少比上一版大 1 |
| `import` | 对象（不在 `ItemContent` 的已知键里，经 §5 原样保留） | — | 导入的条目带 `{"batch": <批次 ID>, "source": <来源>, "at": <时间>}`，用于整批撤销（`npw-core` `remote.rs`，`IMPORT_KEY`） |

客户端约定的扩展键（核心不解析，经 §5 原样保留，格式版本不变；不认识它们的客户端照常读写）：

| 位置 | 类型 | 说明 |
|---|---|---|
| `autofill.auto_type` | 字符串，空 / 无时省略 | 桌面端快捷搜索的自动输入序列（KeePass 风格：`{USERNAME}{TAB}{PASSWORD}{ENTER}`、`{TOTP}`、`{DELAY 500}`、`{S:字段名}` 等，见 `desktop/src-tauri/src/autotype.rs`）；没有时用默认序列 |
| `ssh.agent` | 布尔，缺省视为 `true` | `false`：桌面端 ssh-agent 不提供这把密钥 |

回收站**不是**条目内容的一部分：删除是服务端修订上的 `deleted` 标志（[API.md](API.md) §6）。

## 2. 字段（`Field`）

| 键 | 类型 | 缺省 / 何时省略 | 说明 |
|---|---|---|---|
| `id` | 字符串 | **必需**，条目内唯一 | 模板字段用固定 ID（§4），其他字段用 `f_` + 12 位随机 hex（`new_short_id("f")`）。合并、历史、导入映射都靠它 |
| `label` | 字符串 | 缺省 `""`；总是输出 | 显示名，按创建时的语言写入，之后随用户修改 |
| `kind` | 字符串 | **必需** | 怎么存、怎么显示（下表）。用字符串而不是枚举：新客户端加的类型经过旧客户端仍原样保留 |
| `purpose` | 字符串 | 无时省略 | 自动填充时它是什么（下表），与 `kind` 无关：手机号字段可以是用户名 |
| `value` | 任意 JSON | 缺省 `null`；总是输出 | 除 `address` 外都是字符串；`address` 是对象 |
| `section` | 字符串 | 无时省略 | 所属分区 ID |
| `multiline` | 布尔 | `false` 时省略 | 多行显示；与 `concealed` 组合即“多行密文”（恢复码、私钥、助记词、证书） |
| `generator` | 对象 | 无时省略 | 预留给“上次用的生成器配方”，形状同 `npw_core::generator::Recipe`；目前没有客户端写入，核心原样保存 |

### 2.1 `kind`

| 值 | `value` | 密文（`is_secret`：默认遮挡，修改时旧值进 `history`） |
|---|---|---|
| `text` | 字符串 | |
| `multiline` | 字符串 | |
| `concealed` | 字符串 | 是 |
| `pin` | 只含数字的字符串（如 6 位支付密码） | 是 |
| `email` | 字符串 | |
| `phone` | 字符串 | |
| `url` | 字符串 | |
| `date` | `YYYY-MM-DD` | |
| `month_year` | `YYYY-MM`（卡有效期） | |
| `number` | 数字的字符串形式 | |
| `totp` | `otpauth://` URI，或裸 Base32 密钥 | 是 |
| `address` | `{"country", "province", "city", "district", "street", "postal_code"}`，值都是字符串，新建时为 `{}` | |
| `reference` | 同一保险库中另一个条目的 ID | |
| `file` | 本条目一个附件的 ID | |
| `boolean` | `"true"` / `"false"` | |

“空字段”：`null`、空字符串、或所有值都为空串 / `null` 的对象。

### 2.2 `purpose`

`username`、`password`、`otp`、`email`、`phone`、`name`、`cc-name`、`cc-number`、`cc-exp`、`cc-csc`、`address`、`ssh-private-key`、`ssh-public-key`。

自动填充和列表副标题取**第一个**具有该用途的字段（`by_purpose`）；TOTP 取第一个 `kind = totp` 的字段。

## 3. 其他数组元素

所有数组元素都有条目内唯一的 `id`（合并按 ID 进行，§7），并保留不认识的键。

### 3.1 网址（`UrlEntry`）

| 键 | 说明 |
|---|---|
| `id` | `u_` + 12 位 hex |
| `url` | 网页 URL、裸主机名（可带端口，如 `192.168.1.1:8080`），或 `androidapp://<包名>` |
| `match` | `domain`（可注册域名 eTLD+1，**缺省**）、`host`（主机名，存了端口则含端口）、`starts_with`、`exact`、`regex`、`never`；规则在 `npw-match`，各端一致 |
| `cert_sha256` | Android 应用可接受的签名证书 SHA-256（hex）列表，空时省略 |

### 3.2 passkey（`Passkey`）

| 键 | 缺省 / 何时省略 | 说明 |
|---|---|---|
| `id` | 必需 | `pk_` + 12 位 hex |
| `rp_id` | 必需 | |
| `credential_id` | 必需 | base64url |
| `user_handle` | 缺省 `""` | base64url |
| `user_name` | 缺省 `""` | |
| `user_display_name`、`rp_name` | 空时省略 | |
| `alg` | 缺省 `-7` | COSE 算法，-7 = ES256 |
| `private_key` | 必需 | PKCS#8 DER，base64url |
| `counter` | 缺省 0 | 签名计数 |
| `discoverable` | 缺省 `true` | |
| `created_at` | 0 时省略 | |

### 3.3 附件（`Attachment`）

| 键 | 缺省 / 何时省略 | 说明 |
|---|---|---|
| `id` | 必需 | UUID（v4），也是服务端 blob 名和 AAD 的一部分 |
| `name` | 必需 | 原样保存，落盘时由各端按平台规则清理 |
| `size` | 缺省 0 | 明文字节数 |
| `mime` | 空时省略 | |
| `key` | 必需 | 该附件自己的 32 字节密钥 FK，base64url |
| `blob_sha256` | 空时省略 | 加密 blob 的 SHA-256（hex），下载后校验 |
| `created_at` | 0 时省略 | |

从条目里删掉附件不会删除服务端的 blob（旧修订仍引用它）；只有永久删除整个条目时 blob 才被删除。

### 3.4 密码历史（`HistoryEntry`）

`{id: "h_…", field: <字段 ID>, label: <当时的标签，空时省略>, value: <旧值>, until: <失效时间>}`。保存前 `record_changes_from(previous)` 把**上一版中非空的密文字段**（`concealed`、`pin`、`totp`）里被改掉或删掉的值追加进来，并把 `updated_at` 设为 `max(现在, 上一版 + 1)`。非密文字段的旧值只在服务端修订历史里。

### 3.5 冲突（`Conflict`）

| 键 | 说明 |
|---|---|
| `id` | `c_` + 12 位 hex |
| `path` | 冲突的位置，用 `/` 连接的 JSON 路径，数组元素用其 `id`：如 `fields/password/value`、`title`、`notes`；空串表示整个条目 |
| `label` | `fields/<id>/…` 路径时为该字段的标签（优先取远端的），其他为空串（界面自己命名）；总是输出 |
| `value` | 没被采用的值（本设备的值） |
| `kept` | 记录冲突时被采用的值，`null` 时省略 |
| `device` | 记录冲突的设备 ID，空时省略 |
| `at` | 时间 |

冲突一直留在条目里，直到用户在界面里处理（选一个、都保留、或忽略）。

预设的 `id` 只是预设本身的名字：网页 / 桌面（`ItemEditor.svelte`）和 Android（`Editor.kt`）加入时都换成新的随机 `f_` ID，所以同一条目可以加多个，也不会与模板字段 ID 冲突。菜单里另有一个通用的“多行密文”字段。

## 5. 未知键保留

- `ItemContent`、`Field`、`Section`、`UrlEntry`、`Passkey`、`Attachment`、`HistoryEntry`、`Conflict`、`autofill`、`ssh` 都有 `#[serde(flatten)] extra`：读入时不认识的键放进 `extra`，写出时原样写回（排在已知键之后）。旧客户端编辑新客户端写的条目不会丢东西（`item.rs` 的 `unknown_keys_survive_round_trip`）。
- `kind`、`purpose`、`match`、`template` 是字符串，不认识的值原样保留。
- 合并对不认识的键同样按 JSON 树三方合并（§7），两边改得不同也会记冲突。
- JSON Schema 在每个对象上都是 `"additionalProperties": true`。

## 6. 版本规则

`format` = `MAJOR.MINOR`（两段十进制整数）。

- MINOR 只允许**增加可选键**。已有键永不改名、改类型、改含义、复用；废弃的键继续可读。
- 读到更高 MINOR：可以编辑，未知键保留，写回时 `format` **不降**（仍写那个更高的 MINOR）。
- 读到更高 MAJOR：**只读**，界面提示更新客户端，绝不写回。合并时若任一方是只读，本设备的修改保留但停止推送（`rejected`：“the item was changed by a newer version of NyaPassword”）。
- 解析不了的条目（例如更高 MAJOR 改了结构）：只构造一个只有 `template`、`title` 的最小视图，`format` 原样，只读。
- 没有 `format` 或不是 `数字.数字`、不是 JSON：解码错误（`FormatError`），健康检查会报告。
- 升级不批量重写：条目在下次被编辑保存时才按新格式写出（`encode_item` 把低于当前版本的 `format` 提到 `"1.0"`）。
- 加密时 AAD 绑定 `format_major = max(条目 format 的 MAJOR, FORMAT_MAJOR)`（`format_major_of`），同一个值作为 `format_major` 随修订交给服务端（[加密规格.md](加密规格.md) §6）。

对应代码：`npw-model/src/format.rs` 的 `decode_item`（返回 `DecodedItem { content, raw, version, read_only }`）、`encode_item`、`format_major_of`。

## 7. 三方合并（`merge.rs`）

同步时本设备有未推送的修改（local），服务端又有新修订（remote），以双方最后一致的版本（base，即本地保存的服务端修订）为基准合并：`merge_items(base, local, remote, device)`。合并在 JSON 树上进行：

1. 两边相同 → 取之；只有一边相对 base 改了 → 取改的一边。
2. 一边删除、一边修改 → **保留修改**。
3. 两边都改且不同：
   - 顶层 `updated_at` 取较大值，`created_at` 取较小值，`format` 取较高版本（不记冲突）；
   - 两边都是对象 → 按键递归合并（键顺序：remote 的键，再补 local 独有的、base 独有的）；
   - 顶层 `fields`、`sections`、`urls`、`passkeys`、`attachments`、`history`、`conflicts` 且两边每个元素都有唯一 `id` → 按 `id` 逐个元素递归合并，双方新增的都保留（顺序：remote 的顺序，再补 local 新增的）；
   - 顶层 `tags` → 集合合并：两边都有的保留，一边新增的保留，一边删除的删除；
   - 顶层 `notes`（两边都是字符串）→ 用 `diffy` 按行三方合并，合并失败按下一条处理；
   - 其他 → **冲突**：结果取 remote 的值，local 的值记入 `conflicts`（`path`、`label`、`value` = local、`kept` = remote、`device`、`at`）。
4. 没有 base（例如服务端历史与本地分叉）时，两边不同的值都按冲突处理，两份都留下。
5. 合并结果万一不再符合结构（正常输入不会发生）：保留 remote，把整个 local 条目作为 `path = ""` 的冲突记下。

任何用户输入过的值都不会被丢掉：它要么在结果里，要么在 `conflicts` 里，要么（更旧的值）在服务端修订历史里。

回收站状态不在条目内容里，由 `npw-core` `sync.rs` 的 `apply_remote` 单独决定：两边一致取之；本设备改了删除状态而远端改了内容 → 内容修改胜（条目恢复）；远端改了删除状态而本设备改了内容 → 同样修改胜。合并结果作为基于远端修订的新修订推送。

重新生成（只允许在该版本发布前）：`$env:NPW_BLESS=1; cargo test -p npw-core --test compat`。加了键的新版本：增加 `FORMAT_MINOR`，把 schema 复制到 `format/history/v1.<MINOR>/` 并生成新的样例目录，旧目录永不修改。
