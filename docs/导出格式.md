# NyaPassword 导出格式

本文描述 `npw-export` 产生的三种导出（设计文档 §8.6、§9.3）。库本身不读写文件，只把解密后的保险库转换成字节；各端负责保存、命名和提示风险。

| 导出 | 函数 | 加密 | 无损 | 用途 |
|---|---|---|---|---|
| 原生加密 | `export_native` / `open_native` | 主密码 + Secret Key | 是 | 逃生通道、定期离线备份、迁移到另一个 NyaPassword 账户 |
| KDBX 4 | `export_kdbx` / `export_kdbx_with` | KDBX 自己的密码 | 结构有损，数据不丢 | 不依赖本软件也能读：KeePassXC、KeePassDX、Strongbox |
| CSV | `export_csv` | **无（明文）** | 否 | 表格软件、其他密码管理器 |

## 1. 原生加密导出（format 1）

建议扩展名 `.npwexport`。文件由三部分组成：

```
NYAPASSWORD-EXPORT\n          魔数行，19 字节
{"format":1,...}\n            文件头：一行紧凑 UTF-8 JSON，以 \n 结尾
<payload>                     二进制密文，直到文件末尾
```

### 1.1 文件头

```json
{
  "format": 1,
  "created_at": 1759536000000,
  "export_id": "3f2b8c1e-0000-4000-8000-000000000000",
  "account_login": "alice@example.com",
  "kdf": { "alg": "argon2id", "m": 65536, "t": 3, "p": 4 },
  "salt": "<16 字节，base64url>",
  "secret_key_required": true,
  "wrapped_key": "<npw-crypto 信封，base64url>"
}
```

| 键 | 含义 |
|---|---|
| `format` | 文件格式版本，当前为 `1`。读取方遇到不认识的版本直接拒绝（`UnsupportedVersion`） |
| `created_at` | 导出时间，UTC 毫秒 |
| `export_id` | 每次导出随机生成的 UUID，绑定进所有关联数据（AAD） |
| `account_login` | 导出账户的登录名，解锁前就能显示“这是哪个账户的导出” |
| `kdf` | Argon2id 参数，与账户的 `KdfParams` 同形 |
| `salt` | 每次导出新生成的 16 字节盐（不复用账户盐） |
| `secret_key_required` | 恒为 `true`：解锁永远需要 Secret Key |
| `wrapped_key` | 随机导出密钥 EK 用 AUK 封装后的信封 |

文件头**不含任何条目信息**（连条目数都没有）。未知键在读取时忽略。

### 1.2 密钥与加密

```
AUK         = kdf::derive_master(主密码, Secret Key, salt, kdf).auk
EK          = 32 字节随机
wrapped_key = envelope::seal(AUK, EK, aad::export(export_id))
payload     = stream::encrypt(EK, aad::export(export_id) ‖ SHA-256(文件头行), 明文 JSON)
```

- 派生方式与账户解锁完全相同（NFKD + Argon2id，与 Secret Key 的 HKDF 结果异或，再 HKDF 出 AUK），只是盐和参数取自文件头。所以只有主密码或只有 Secret Key 都打不开，泄露的导出文件无法只靠暴力破解主密码打开。
- `aad::export(export_id)` = ASCII `npw/export/v1` ‖ export_id 的 16 个原始字节。
- 载荷的 AAD 额外附上**文件头行**（不含结尾 `\n`）的 SHA-256，所以改动文件头的任何一个字节（登录名、时间等）都会让载荷认证失败。
- `stream` 是附件用的 STREAM 构造（XChaCha20-Poly1305，每 1 MiB 一块，nonce = 前缀 ‖ 块序号 ‖ 末块标志），防截断、防重排、防追加。
- 不压缩：保持纯 Rust、能编译到 WASM，也避免压缩带来的长度侧信道。

读取时的错误：

| 情况 | 错误 |
|---|---|
| 不以魔数开头 | `NotAnExport` |
| 文件头 JSON 损坏、参数越界 | `Malformed` |
| 主密码或 Secret Key 错误（无法区分），或 `wrapped_key` / `salt` / `kdf` 被改 | `WrongPassword` |
| 载荷或文件头其他部分被改、被截断、被追加 | `Corrupted` |

`kdf` 只检查上限（内存 ≤ 1 GiB、迭代 ≤ 64、并行 ≤ 16），防止恶意文件让客户端分配巨量内存。

### 1.3 载荷明文

```json
{
  "vaults": [
    {
      "name": "个人",
      "items": [
        {
          "content": { "format": "1.0", "template": "login", "title": "Example", "...": "…" },
          "deleted": false,
          "attachments": [
            { "meta": { "id": "a1", "name": "recovery.txt", "size": 1234, "key": "…" }, "data_b64": "<附件明文，base64url>" }
          ]
        }
      ]
    }
  ]
}
```

- `content` 就是条目内容的明文 JSON（设计文档 §5.2），原样写入，包括未知键、字段 ID、分区、网址匹配方式、passkey、历史、冲突、自动填充设置。
- `deleted` 为 `true` 表示条目在回收站。
- 附件按导出时提供的元数据 + 明文写入。
- 导出 → 打开得到的 `Vec<ExportVault>` 与导出时**逐字段相等**（测试中直接 `assert_eq!`）。

## 2. KDBX 4

用 `keepass` crate（0.15，`save_kdbx4`）写出，Argon2id（默认 64 MiB、10 次、2 线程，可用 `KdbxOptions` 调整），外层 AES-256，内层 ChaCha20，GZip 压缩。

| NyaPassword | KDBX |
|---|---|
| 保险库 | 根组 `NyaPassword` 下的一个组 |
| 已删除的条目 | 组 `回收站`（写进元数据，作为数据库的回收站），其下按保险库再分组 |
| 标题 | `Title` |
| 第一个用途为 `username` 的字段 | `UserName` |
| 第一个用途为 `password` 的字段 | `Password`（受保护） |
| 第一个网址 / 其余网址 | `URL` / `KP2A_URL_1`、`KP2A_URL_2`…（KeePassXC、KeePass2Android 认这个名字） |
| 备注 | `Notes` |
| 第一个 TOTP 字段 | `otp`，`otpauth://` URI（裸 base32 密钥转换为 `otpauth://totp/<标题>:<用户名>?secret=…&period=30&digits=6&algorithm=SHA1&issuer=<标题>`） |
| passkey | KeePassXC 属性 `KPEX_PASSKEY_USERNAME`、`KPEX_PASSKEY_CREDENTIAL_ID`、`KPEX_PASSKEY_PRIVATE_KEY_PEM`（PKCS#8 → `-----BEGIN PRIVATE KEY-----` PEM）、`KPEX_PASSKEY_RELYING_PARTY`、`KPEX_PASSKEY_USER_HANDLE`；KeePassXC 每个条目只支持一个 passkey，第 2 个起各复制一个条目 `标题 (passkey N)`（复制字段和网址，不复制附件和历史）；条目没有网址时 `URL` 设为 `https://<rp_id>` |
| 其他字段（所有模板） | 自定义字符串字段，名字是标签，在分区里则为 `分区: 标签`，重名追加 ` (2)`、` (3)`；`concealed`、`pin`、`totp` 受保护；空字段跳过；地址写成 JSON；`file` 字段写附件名 |
| 附件 | 条目附件，同名的改为 `名字 (2).扩展名` |
| 历史（密文字段的旧值） | KeePass 条目历史：每个旧值一个快照（当前条目把该字段换成旧值），按时间从旧到新，修改时间 = 旧值失效时间 |
| 标签 | KeePass 标签（标签里的 `;` `,` 制表符换成空格）；收藏、归档追加标签 `favorite`、`archived` |
| `created_at` / `updated_at` | 创建 / 修改时间（精确到秒） |
| 模板 | 条目自定义数据 `NyaPassword/template` |

KDBX 表达不了、只在原生导出里保留的：网址匹配方式和 Android 证书指纹、字段类型和生成器设置、分区结构（只剩标签前缀）、自动填充 / SSH agent 设置、未解决的同步冲突、passkey 计数器和显示名、新版本客户端写入的未知键。

## 3. CSV（明文）

> **警告：CSV 是明文。** 所有密码、卡号、恢复码、TOTP 密钥对任何能读到这个文件的程序都可见（同步盘、备份、杀毒软件上传、回收站）。客户端必须先要求重新输入主密码并提示风险，用完建议删除。

- UTF-8 带 BOM，CRLF 换行，RFC 4180 引号规则（Excel / WPS / LibreOffice 直接打开，多行值留在一个单元格里）。
- 列：`vault,title,username,password,url,totp,notes,tags,template,fields`
  - `username` / `password`：第一个对应用途的字段；
  - `url`：第一个网址；`totp`：第一个 TOTP 字段的原值；
  - `tags`：用 `;` 连接；
  - `fields`：其余所有非空字段和其余网址组成的 JSON 数组 `[{"label", "section"?, "kind", "value"}]`，地址是 JSON 对象。
- 不包含：回收站里的条目、附件、passkey（私钥不该进表格）、历史、各种设置。需要这些请用原生导出或 KDBX。
