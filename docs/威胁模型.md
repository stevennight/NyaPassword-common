# NyaPassword 威胁模型

> 展开 [设计方案.md](设计方案.md) §4.1。描述的是**当前代码**提供的保护；引用的代码位置以仓库目录为前缀（`common/`、`server/`、`chrome/`、`desktop/`、`android/`）。密码学细节见 [加密规格.md](加密规格.md)，接口见 [API.md](API.md)。
> 本文中的域名、地址一律是占位值（`example.com`、`203.0.113.x`）。

## 0. 前提与范围

- 个人自建：一个服务端（Docker，只监听本机，Caddy 终止 TLS），一个账户，若干设备（桌面、浏览器扩展、Android、网页版）。
- **服务端对机密性不受信任**：它只应看到密文和必要的元数据。对可用性和“顺序”半受信任：它决定修订顺序，但客户端保留本地副本、能发现部分篡改。
- **客户端设备在用户解锁使用期间受信任**：操作系统、浏览器、客户端程序本身没有被植入恶意代码。
- 用户的主密码不被重用、不被钓走；紧急恢复包（Secret Key、备份离线私钥）离线妥善保管。

## 1. 资产

| 资产 | 在哪里 | 泄露 / 损坏的后果 |
|---|---|---|
| 条目明文（密码、TOTP 密钥、passkey 私钥、SSH 私钥、银行卡、证件、备注、附件） | 只在已解锁客户端的内存中 | 最高：全部账户被接管 |
| 主密码 | 用户脑中；输入时短暂在客户端内存 | 配合 Secret Key 即可解开一切 |
| Secret Key（128 位） | 紧急恢复包；各设备本地副本（设备密钥加密，见加密规格 §3.3） | 单独无用；与主密码一起即可解开一切；没有它服务端数据无法暴力破解 |
| AK / VK / IK / FK | 服务端和本地只有封装后的密文；解锁后在内存 | 等同条目明文 |
| 会话令牌 | 客户端（设备密钥加密）；服务端只存哈希 | 能以该设备身份调用 API：读写**密文**、删除、吊销设备 |
| 服务端 `server.key`、OPAQUE `ServerSetup`、备份 age 私钥 | 服务端数据目录、每个备份 | 能解开备份外层、伪造未知账户的 prelogin 应答；不能解开条目 |
| 备份离线 age 私钥 | 紧急恢复包 | 能解开备份外层，里面仍是条目密文 |
| 管理口令 / TOTP | 管理员；服务端存 Argon2 哈希和 TOTP 密钥 | 管理后台：看到元数据、改备份目标、吊销设备、发邀请码；不能解开条目 |
| 元数据 | 服务端数据库、日志、备份 | 登录名、设备名称 / 平台 / 版本 / 最后在线、IP（审计日志）、条目数、每个修订的大小和时间、哪个设备改的、回收站状态、附件大小、保险库数 |
| 数据完整性与可用性 | 服务端 + 每个设备的副本 + 备份 + 离线导出 | 丢密码 = 项目失败；设计目标“任何情况下都不丢数据” |

## 2. 安全目标

1. 服务端、备份存储、网络上的攻击者**拿不到明文**，也**不能离线暴力破解主密码**（双密钥派生：需要 Secret Key）。
2. 服务端不能伪造或篡改条目内容，不能把密文换位置、换身份（AEAD + AAD）。
3. 登录不向服务端暴露任何可离线验证的东西（OPAQUE）。
4. 自动填充只把凭据交给与保存网址匹配的网页 / 应用，并且要用户在可见的界面上选择。
5. 任何一端的故障或恶意服务端都不应让用户输入过的值永久消失（合并保留冲突、修订只追加、多副本、备份、离线导出）。

## 3. 攻击者

每一节：能拿到什么 → 能做什么 → 做不到什么 → 已有的缓解（代码位置）→ 剩余风险。

### 3.1 备份存储商 / 备份泄露

**能拿到**：对象存储（阿里云 OSS / WebDAV / 目录）上的 `backups/nyapassword-<时间>-s<seq>.tar.zst.age` 和 `attachments/<附件 ID>`。

**没有 age 私钥时**：只能看到对象数量、大小、时间（对象名里有时间和最大 seq）和附件数量、大小。备份是 age X25519 加密的（`common/crates/npw-backup/src/lib.rs` `seal`），附件本身是端到端加密的 STREAM 密文（加密规格 §8）。

**拿到 age 私钥时**（服务端被入侵拿到 `server.key`，或紧急恢复包泄露）：得到数据库快照和 `server.key`，即 §3.2 中“读数据库”能得到的一切，以及备份目标的凭据（数据库里用 `server.key` 加密的设置）。**仍然**解不开条目：需要主密码 + Secret Key；OPAQUE 记录和 `ServerSetup` 都在里面，但能离线猜的对象 LOGIN 含 128 位 Secret Key（加密规格 §7.3）。

**能做**：在不受防删保护的目标上删除或替换备份。防删模式（`protect_mode`，凭据只有写权限 + 存储端 WORM / 版本控制）下服务器凭据删不掉历史备份（`server/src/backup/mod.rs` `backup_to` 在防删模式下不做保留清理）。替换的归档在恢复时能被发现：age 认证加密 + manifest 中每个文件的 SHA-256（`npw_backup::open`）；但持有 age **公钥**（公开的）的人可以构造一个全新的、内容任意的归档——它解得开，只是里面的条目不是你的（无法用你的密钥解密），恢复后客户端全量对账会把本地数据重新上传。

**剩余风险**：
- 元数据泄露（见上）。
- 没有前向保密：主密码和 Secret Key 一旦同时泄露，所有历史备份（含所有旧修订、旧密码）都能解开；密钥层级不轮换。
- 附件目录不经过 age，附件 ID 和大小对存储商可见。

### 3.2 服务器被入侵：读取

**能拿到**：SQLite 数据库、`server.key`、附件目录、进程内存、反向代理（Caddy）上经过的全部请求。

| 能得到 | 不能得到 |
|---|---|
| 全部密文（条目每个修订、封装的密钥、保险库元数据、附件 blob） | 任何明文、任何未封装的密钥 |
| 登录名、账户 ID、KDF 参数与盐、OPAQUE 记录和 `ServerSetup` | 主密码；离线暴力破解所需的 Secret Key |
| 设备列表、审计日志（含 IP）、条目数量、修订大小和时间、哪个设备写的、回收站状态 | |
| `server.key`：从而解开数据库里加密的备份目标凭据、通知渠道密钥（SMTP 口令、Telegram token 等）、服务端 age 私钥（所有备份的外层） | |
| 管理口令的 Argon2 哈希（可离线猜，弱口令有风险）、管理 TOTP 密钥（明文存在 `settings`） | |
| 运行期间经过的 access / refresh token（TLS 在 Caddy 终止，服务端看到明文请求）；WebSocket 的 token 在查询字符串里，若 Caddy 开了访问日志会被记下 | |

**缓解**：端到端加密与双密钥派生（`common/crates/npw-crypto/src/kdf.rs`）；服务端只存令牌的 SHA-256（`server/src/auth.rs` `hash_token`）；OPAQUE 不存可离线验证的哈希（`common/crates/npw-crypto/src/opaque.rs`）。

**剩余风险**：拿到有效令牌就能以该设备身份读写密文——它不能解密，但能执行 §3.3 的所有破坏。

### 3.3 服务器被入侵：篡改（恶意服务端）

**做不到**：
- 伪造或修改条目内容：内容由 IK 做 AEAD，IK 由 VK 封装，VK 由 AK 封装，都在客户端（`common/crates/npw-core/src/items.rs` `open_item` / `seal_item`）。
- 把一个条目的密文换给另一个条目、搬到另一个保险库、把 AK 当 IK 呈现、改标格式大版本：AAD 绑定标签、保险库 ID、条目 ID、`format_major`（`common/crates/npw-crypto/src/aad.rs`）。
- 往保险库里塞条目、凭空造一个保险库：需要 VK / AK。
- 替换附件：条目内容里有 `blob_sha256`，且 STREAM 有 AEAD（`common/crates/npw-core/src/remote.rs` `attachment`）。
- 把 KDF 参数降到很弱：客户端拒绝低于 16 MiB / t=1 / p=1 的参数（`KdfParams::validate`，在 `sign_in`、每次 `unlock` 前和接受 `GET /v1/account` 里的新参数前检查）。而且没有 Secret Key，弱参数也没有用。
- 通过登录拿到密码：OPAQUE。

**能做**：
- **拒绝服务、删除、隐藏**：不响应、返回错误、拒绝写入。这是设计上接受的（设计方案 §4.1）。
- **静默回滚单个条目的内容**：服务端可以把某条目的旧修订（旧密文在同一 IK、同一 AAD 下仍然有效）以一个**新的**修订号发出。修订号和 seq 都不在 AAD 里，客户端只能发现“修订号变小”这种朴素回滚（`common/crates/npw-core/src/sync.rs` `apply_remote` 的 `rollbacks_detected`，此时忽略该记录）和“保险库 seq 变小”（触发全量对账，把本地较新的版本重新上传）。
- **改回收站状态**：`deleted` 标志是服务端元数据，不受认证，服务端可以把条目移入或移出回收站。
- **让客户端删除本地副本**：
  - 在 `changes` 的 `purged` 列表里列出任意条目 ID，客户端会删掉没有待推送修改的本地条目（`sync.rs` `apply_purge`）；
  - 对任何请求回答 `device_revoked`：客户端视本机为丢失设备，清除该账户的全部本地数据，**包括未推送的修改**（`client.rs` `on_revoked` → `wipe_local`）。这是“吊销能真正生效”（§3.8）的代价。
- 在 `GET /v1/account` 里不返回某个保险库**不再**能删掉本地副本：客户端保留它（含未推送的修改），只是暂停同步并报告（`client.rs` `apply_account_resp`，`SyncReport.vaults_missing_on_server`）。
- 让设备无法离线解锁**做不到**：`apply_account_resp` 只接受通过 `KdfParams::validate`、盐长度和 base64 检查的新解锁材料（封装的 AK、KDF 参数、盐），并保留上一份确认能解锁的材料作为备用；离线解锁先试当前的、再试备用的（`client.rs` `open_account_key`）。服务端发来的垃圾最多让这台设备多做一次 Argon2。
- **替换网页版代码**：网页版（以及管理后台）由服务端自己提供（`server/src/web.rs`）。被入侵的服务端可以下发修改过的 JavaScript，在用户于网页版输入主密码和 Secret Key 时直接拿走。这是所有“服务端提供网页版”的端到端加密方案的共同限制；CSP 和 `X-Frame-Options` 防不了服务端本身。
- **为将来的共享替换公钥**：`AccountResp.public_key` 不受认证；客户端目前不核对它与 `encrypted_private_key` 解出的私钥是否匹配。v1 没有共享，暂无影响。

**缓解**：多副本（每台设备的本地副本、修订只追加、备份）；同步后摘要比对；epoch 变化和 seq 回退触发全量对账并重新上传服务端丢失的数据（`sync.rs` `reconcile` / `restore_onto`）；桌面端定期离线导出（原生 + KDBX，见 [导出格式.md](导出格式.md)），与服务端无关。

**剩余风险**：上面“能做”中的回滚、回收站篡改、诱导删除本地副本、网页版代码替换。建议：日常用桌面端 / 扩展 / Android，网页版只在临时需要时用；保留离线导出。

### 3.4 网络攻击者

**能拿到**：TLS 之外的东西（流量大小、时间、服务器 IP）；若能伪造证书（被信任的 CA 出问题、用户点了证书警告），则等同 §3.2 中“经过反向代理的请求”加 §3.3。

**做不到**：即使看到明文 HTTP，也拿不到主密码、Secret Key、任何密钥或条目明文：登录是 OPAQUE（不传送密码或其等价物），所有数据都是端到端加密的。

**剩余风险**：客户端没有证书固定；令牌在 TLS 被破时可被截获；网页版在 TLS 被破时可被注入代码（同 §3.3）。服务端默认只监听 `127.0.0.1:8087`（`server/src/config.rs`），不应把它直接暴露到公网，否则 `X-Forwarded-For`（`trust_proxy` 默认开）可被伪造来绕过按 IP 的登录限速（按登录名的限速仍然有效）。

### 3.5 恶意网页 / 恶意 iframe（对浏览器扩展）

扩展的结构（`chrome/src/entrypoints/background.ts` 文件头）：Service Worker 持有唯一的核心（WASM）；内容脚本运行在隔离环境（isolated world），**只能请求填写和提出保存**；所有界面（内联菜单、保存提示、弹窗）都是扩展源的页面，以 iframe 形式嵌在网页里，网页读不到它们的内容。

**做不到**：
- 读取扩展存储、内存中的密钥或其他站点的条目：页面脚本与内容脚本、扩展页面隔离。
- 冒充别的站点：后台判断来源用的是 Chrome 报告的发送方 frame 的 `sender.url` / `sender.origin`，不是页面提供的数据（`background.ts` `fromContent`）。
- 拿到与本 frame 网址不匹配的条目：`credentialsFor` 重新计算该 frame 网址的候选条目，所选条目不在其中就拒绝（`background.ts` 156–158 行）。
- 让扩展在 `http` 页面填写银行卡（`secureContext` 检查），或在 `http` 页面加载时自动填写。
- 冒用 passkey：WebAuthn 请求由 MAIN world 脚本转交，来源仍取自 Chrome 报告的 frame；RP ID 必须是来源主机本身或其可注册后缀，且必须是 https（`localhost` 除外），IP 地址来源被拒绝（`common/crates/npw-passkey/src/rp.rs`）。

**能做**：
- 用户在匹配的站点上填写后，页面脚本当然能读到表单里的值——这是填写的目的。若匹配的站点存在 XSS，攻击者在用户填写时得到凭据。
- 触发保存提示（骚扰），并通过“是否提示保存 / 更新”推断某个用户名 / 密码组合是否已为**本站**保存。
- 发现扩展的存在（注入的宿主元素）。

**iframe**：内容脚本运行在所有 frame（`allFrames: true`），匹配按 **iframe 自己的网址**。恶意页面嵌入真实站点的 iframe 时，填写发生在真实站点的 iframe 内，外层页面读不到跨源 iframe 的内容。

**剩余风险**：设计方案 §10.4 的“跨域 iframe 里的登录框要提示用户；顶层页和 iframe 不同源时默认不自动填”**尚未实现**：内联菜单在任何 frame 都可用，可选的“页面加载时自动填写”（默认关）也不检查顶层页来源。`domain` 匹配方式下，同一可注册域名下的任何子域都会匹配（如果某站点在子域上托管用户内容，该子域也能触发填写）。

### 3.6 钓鱼：相似域名

**缓解**（`common/crates/npw-match/src/lib.rs`）：
- 网址先用 `url` crate 解析，国际化域名转成 punycode；`domain` 方式比较的是公共后缀表（`psl` crate）算出的可注册域名（eTLD+1）。`examp1e.example`、`example.com.evil.example`、同形异义字的 `xn--…` 域名都与 `example.com` 不同，**不会出现填写建议**——“没有建议”本身就是钓鱼信号。
- IP 地址和单标签主机名（`nas`、`localhost`）只匹配自己。
- 保存为 `https` 的登录不会建议给**其他主机**的 `http` 页面。
- `starts_with` 和 `exact` 比较的是规范化后的完整 URL（`https://example.com` 规范化为 `https://example.com/`，所以不会前缀匹配 `https://example.com.evil.example/`）。

**剩余风险**：
- 同一主机的 `http` 页面会匹配 `https` 保存的登录（`host` 质量的匹配不看协议）；中间人可以在 `http://` 版本上注入登录表单诱导用户点选填写。
- 内置“等价域名”（淘宝 / 天猫 / 支付宝、QQ / 微信、Google / YouTube 等，`BUILTIN_EQUIVALENTS`）扩大了信任范围（等价匹配同样遵守“`https` 保存的登录不建议给其他主机的 `http` 页面”）。
- 用户自定义的 `regex` 规则可能过宽（不锚定时会匹配到别的站点），由用户负责。

### 3.7 点击劫持（内联菜单）

**缓解**：
- 内联菜单是扩展源的 iframe，页面无法读取或伪造它的内容；凭据只会填给该 frame 网址匹配的条目（§3.5）。
- 填写前检查菜单是否可信（`chrome/src/entrypoints/content.ts` `menuTrusted`，119–130 行）：iframe 仍在文档中、打开已满 300 毫秒（防止“刚弹出就被点”）、自身 `visibility`、`display` 正常且 `opacity` 为 1、外层宿主元素 `opacity` 为 1。
- 网页版和管理后台禁止被嵌入：`X-Frame-Options: DENY`、CSP `frame-ancestors 'none'`（`server/src/web.rs`）。

**剩余风险**：没有检查是否有页面元素**覆盖**在菜单上（例如盖一层 `pointer-events: none` 的伪装内容，让用户以为点的是别的东西），也没有检查祖先元素的 `filter`、`transform`、`clip-path`。由于凭据只会填给本站，最坏结果是“在用户没有真正同意时把本站的凭据填进本站的页面”，对存在 XSS 或托管不可信内容的站点有意义。

### 3.8 设备丢失或被盗

**锁定状态**：本地副本里有条目密文、账户状态（登录名、服务器地址、KDF 参数、盐、封装的 AK——这些不是秘密）、用设备密钥加密的 Secret Key 和会话（加密规格 §3.3）。攻击者要解锁就要主密码；能否离线暴力破解主密码取决于能否拿到 Secret Key，即设备密钥的保护强度：

| 端 | 设备密钥 | 拿到设备后 |
|---|---|---|
| 桌面 | 系统凭据存储（Windows 凭据管理器，受用户登录凭据保护） | 不知道系统登录密码时取不出 Secret Key；以用户身份运行代码（或用了回退文件 `device-key.bin`）时可以取出，然后以 Argon2id（默认 64 MiB、3 次、4 路）的代价离线猜主密码 |
| Android | `noBackupFilesDir` 中的文件，由 Android Keystore 的 AES 密钥包装（不要求用户认证，只把文件绑定到这台手机） | 密钥材料取不出 Keystore；但能以本应用身份在这台手机上运行代码（如已 root）就能让 Keystore 解开设备密钥，进而离线猜主密码 |
| 浏览器扩展、网页版 | IndexedDB 中的明文设备密钥，与副本放在一起 | 拿到浏览器配置目录即可取出 Secret Key，然后离线猜主密码 |

快速解锁：Windows Hello 需要用户在场，且只在本次运行用主密码解锁过、距上次主密码解锁不到 14 天时可用（`desktop/src-tauri/src/quick_unlock.rs`）；Android 生物识别密钥要求用户认证，新增指纹即失效（`android/app/src/main/java/app/nya/password/core/Keys.kt`）；扩展的 AK 只在 `chrome.storage.session`（内存），浏览器关闭即失效。

**解锁状态**：等同拿到明文。自动锁定（空闲、系统锁屏）限制了时间窗口。

**吊销设备**（`DELETE /v1/devices/{id}`，或管理后台）：标记吊销（设备行保留）并推送 `device_revoked` 事件。会话**不删除**，所以被吊销设备的 access / refresh token 都得到 `device_revoked`（`server/src/auth.rs` `authenticate`、`refresh`）；会话过期后重新登录时出示该设备 ID 也被拒绝（`issue_session`）。`npw-core` 收到 `device_revoked` 不会重新登录，而是立即清除该账户在本机的一切：账户状态、Secret Key、会话、整个本地副本（含未推送的修改）、缓存的附件、内存中的密钥（`common/crates/npw-core/src/client.rs` `on_revoked` / `wipe_local`）。设备只要还联网、运行的是正常客户端，下一次请求就会自我擦除。

**剩余风险**：设备离线时吊销不生效（本地副本仍可用主密码离线解锁），被改过的客户端可以无视 `device_revoked`、并在知道 LOGIN（解锁状态的内存里有）时不带设备 ID 登录得到新设备——此时只有改主密码才能把它挡在服务端之外；扩展 / 网页版的 Secret Key 保护较弱。对付被改过的客户端，补救是改主密码（会让其他设备的会话全部失效、旧 LOGIN 不再能登录），但设备上已有的本地副本和 Secret Key 不会因此失效——旧副本仍可用旧主密码离线解开。

### 3.8.1 使用前需要验证（`reprompt`）

条目可以设置“使用前需要验证”（[条目格式.md](条目格式.md) §1 的 `reprompt`，相当于 Bitwarden 的“主密码重新提示”；从 Bitwarden 导入时自动转换，`common/crates/npw-import/src/bitwarden.rs`）。

**防的是**：已解锁但无人看管的设备、旁人偷看。拿到已解锁设备的人，不知道主密码（也过不了 Windows Hello / 指纹）就看不到、复制不了、填不出这类条目的秘密。

**各端的做法**：
- 网页版、桌面端、扩展的密码库页（`common/web/src/components/RepromptGate.svelte`、`lib/reprompt.ts`）：只显示标题、摘要（用户名）和网址；字段值、显示 / 复制、一次性密码、附件下载、passkey 详情、历史版本、冲突值和编辑都要先验证。验证只对这一个条目有效，打开其他条目或锁定后失效。主密码由核心校验（`Client::verify_password`），不改变锁定状态。桌面端也可以用 Windows Hello：开启了快速解锁时走与快速解锁相同的签名 → 解包账户密钥 → 核心 `verify_key` 核对的路径，否则只用 `UserConsentVerifier` 做在场确认（`desktop/src-tauri/src/verify.rs`）。
- 浏览器扩展：由 Service Worker 强制，不只是界面（`chrome/src/entrypoints/background.ts`、`src/lib/reprompt.ts`）。用户在内联菜单、提示框或弹窗（都是扩展自己的页面）里输入主密码（`ctx:verify` / `popup:verify`）后，Service Worker 只为这一个上下文（nonce）、这一个条目放行**一次**（2 分钟内有效），否则拒绝填写（错误码 `reprompt`）。快捷键填写和页面加载时自动填写跳过这类条目；保存 / 更新提示遇到同用户名的这类条目时一律不提示，网页不能通过“是否弹出提示”来猜它的密码；银行卡、身份同样要验证；passkey 登录要在提示框里先输入主密码再签名。
- 桌面端快捷搜索：自动输入、复制密码 / 验证码前在快捷搜索窗口验证（`quick_verify`，一次验证放行一次）。SSH agent：这类密钥**每次**签名都要在确认窗口里验证，不提供“锁定前都允许”（`prompts.rs` 在验证前拒绝“允许”）。
- Android：详情、编辑页同样遮挡（BiometricPrompt 或主密码，`core/Reprompt.kt`）；自动填充里这类条目的数据集不带任何值，选中后先在 `AutofillActivity` 验证，再返回真正的数据集；“搜索 NyaPassword”和保存提示的“更新”同样先验证，保存提示不显示“已是这个密码”；凭据提供程序本来每次都验证。

**防不了**：
- 它**不是加密**：这类条目和其他条目用同样的密钥加密，解锁后同样解密在内存里。能读已解锁程序内存、截屏、记录键盘的恶意软件（§3.9）照样拿得到；被改过的客户端也能直接绕过。
- 扩展的完整密码库页和弹窗本身就能调用 Service Worker 读任何条目（`call`）。强制的是网页和内容脚本能触发的路径（填写、passkey、保存提示）；扩展页面里的遮挡与网页版一样只是界面层。
- 同一用户的其他程序可以读剪贴板：验证后复制的秘密照常进剪贴板（桌面端 90 秒后清除）。
- 桌面端未开启快速解锁时，Windows Hello 的在场确认只证明“有人通过了 Hello”，不证明知道主密码。
- 安全检查、健康检查、同步、合并、导出照常进行（在核心里，不经过界面）；导出本来就要主密码。

### 3.9 设备上的恶意软件

不在防护范围：解锁期间能读内存、截屏、记录键盘的恶意软件可以拿到一切，任何密码管理器都防不住。只做最小化：

- 锁定时丢弃全部密钥和解密缓存（`client.rs` `lock`）；Rust 侧密钥类型清零（`Key32`、`SecretKey` 的 `ZeroizeOnDrop`）。WASM / JavaScript / Kotlin 侧的字符串无法可靠清零。
- 剪贴板：桌面复制的秘密 90 秒后（若仍在剪贴板）和退出时清除（`desktop/src-tauri/src/clipboard.rs`），Windows 上标记为不进剪贴板历史、不上传云剪贴板（`desktop/src-tauri/src/platform/windows.rs`，`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory`）。
- Android：所有界面 `FLAG_SECURE`（禁止截屏和最近任务预览，`android/.../ui/Unlock.kt`）。

### 3.9.1 桌面端的本地接口：ssh-agent、浏览器扩展联动、自动输入

这三样都向本机其他进程开放能力，所以单列。攻击者模型：**同一用户下的其他程序**（不一定是能读内存的恶意软件）、其他用户、远程主机。

**ssh-agent**（`desktop/src-tauri/src/ssh_agent.rs`、`ipc.rs`）：
- 命名管道的 DACL 只给当前用户 SID，拒绝远程客户端；首个实例独占创建，管道已被占用（Windows OpenSSH 服务、Bitwarden 等其他 agent）时报告占用者而不共用；Unix socket 权限 0600。
- 只提供 `ssh_key` 条目的公钥（条目可用 `ssh.agent = false` 退出），不接受添加 / 删除密钥；拒绝 SHA-1 的 `ssh-rsa` 签名。
- **每次签名弹窗确认**（显示密钥、用途——SSH 登录用户名 / 服务器主机密钥指纹、Git SSHSIG 命名空间——以及请求进程和父进程）；“锁定前都允许”只到下次锁定；确认窗口出现后 0.7 秒内按钮无效、键盘不能批准，避免用户正在别处打字时误按。锁定时请求等待用户解锁（最多 60 秒），不会用未解锁的数据。
- 调试版的 `NPW_TEST_AUTO_APPROVE=1`、`NPW_TEST_WEBVIEW_ARGS` 只在 `debug_assertions` 下编译，发布版没有。
- **剩余风险**：同一用户的程序可以发起签名请求，靠用户确认挡住；用户批准了“锁定前都允许”后，同一用户的任何程序都能用这把密钥签名直到锁定（与 OpenSSH agent 转发的风险相同）。

**浏览器扩展联动**（`desktop/src-tauri/src/browser_bridge.rs`、`chrome/src/lib/desktop-link.ts`）：
- Native Messaging 宿主清单只允许设置里填写的扩展 ID（`allowed_origins`），桌面端再按 Chrome 传给宿主的来源核对一次；宿主到应用的本地通道同样只对当前用户开放。
- 配对必须由用户在桌面端确认，两边显示同一个 6 位数字（扩展公钥的 SHA-256 派生），并且只接受与桌面端**同一账户、同一服务器**的扩展；桌面端只保存扩展的公钥。
- 账户密钥用扩展的长期 P-256 公钥封装（临时 ECDH + HKDF-SHA256〔盐为扩展每次给的随机 nonce，info 含双方公钥与账户 ID〕+ AES-256-GCM〔AAD 含账户 ID〕）；扩展的私钥是不可导出的 WebCrypto 密钥（IndexedDB）。扩展拿到后调用 `unlockWithKey`，它用账户私钥的密文校验密钥：冒充桌面端的进程只能让扩展解锁失败，不能塞进别的密钥。
- **剩余风险**：同一用户的恶意程序可以连接本地通道冒充扩展，但拿不到配对私钥就解不开封装；能读取浏览器配置目录的恶意程序可以拿走 IndexedDB 中的私钥（不可导出只防网页脚本，不防磁盘读取）并在桌面端解锁时取得账户密钥——这属于 §3.9 的范围。取消配对在桌面端设置或扩展弹窗里。

**自动输入**（`autotype.rs`、`platform/windows.rs`）：打开快捷搜索时记下前台窗口，输入前切回并确认它在前台，**每个字符前**都检查前台窗口没变，变了就停止；目标窗口与条目不匹配时也允许输入（像 KeePass），由用户选择负责。以管理员身份运行的程序会被 UIPI 拦截输入，界面会提示。

### 3.10 冒名 Android 应用

**缓解**：
- 应用以 `androidapp://<包名>` 匹配，条目可记录可接受的签名证书 SHA-256（`cert_sha256`）。有记录时，调用方应用的签名证书必须在列表里（`common/crates/npw-ffi/src/lib.rs` `app_cert_allowed`）；用户在 Android 上把应用关联到条目时会记下证书（`link_app`）。
- 浏览器报告的网页域名（`webDomain`）只对被识别为浏览器的应用采信：Google 特权浏览器列表按包名 + 证书识别（`android/.../autofill/Fill.kt` `Browsers`）。
- passkey 的应用来源是 `android:apk-key-hash:<证书 SHA-256>`（`android/.../core/Origins.kt`）。

**剩余风险**：
- 条目里的 `androidapp://` 网址没有记录证书时（例如从 Bitwarden 导入的），**任何同包名的应用**都能得到建议。
- 不在特权列表里的国内浏览器只按包名识别（`Browsers.BY_PACKAGE`，代码注释已说明）：在没有装真浏览器的手机上，冒用这些包名的应用可以声称自己在任意网站上。
- 填写仍需用户在系统自动填充界面选择条目。

### 3.11 管理后台

**缓解**：独立的管理口令（Argon2）+ 可选 TOTP；每 IP 每 15 分钟 10 次尝试；会话只在内存、12 小时；与用户账户无关，**拿不到任何条目密钥**（`server/src/admin.rs`）。

**能做（攻击者拿到管理权限时）**：看到账户、设备、全部审计日志（含 IP）；吊销设备、生成邀请码；修改备份设置——包括**添加自己的 age 接收者**或指向自己存储的备份目标，从而拿到之后所有备份（仍是条目密文，见 §3.1）；看到通知渠道的配置（SMTP 口令、Telegram bot token 在 `GET /v1/admin/backup` 中显示为掩码，只写不读；Webhook 和 Bark 地址原样显示，其中可能含密钥）。

**剩余风险**：TOTP 在有效窗口内可重放；管理口令只要求 ≥ 12 个字符。

### 3.12 恶意文件：导入、导出、备份

- 导入器解析不可信文件（Bitwarden zip / JSON / 加密 JSON / CSV、1PUX、KDBX、CSV）：有健壮性测试（`common/crates/npw-import/tests/robustness.rs`）和 CI 模糊测试；导入先预览，写入是原子批次，可整批撤销。
- 原生导出文件头的 KDF 参数只检查上限，防止恶意文件让客户端分配巨量内存（[导出格式.md](导出格式.md) §1.2）。
- 备份恢复：解包时拒绝含 `..`、`/`、`\` 的文件名，且不覆盖已存在的文件（`npw_backup::extract_to`）；恢复前先 `integrity_check` 并核对条目数（`server/src/restore.rs`）。

### 3.13 更新与供应链

- 桌面端自更新校验 `SHA256SUMS` 的 minisign 签名（公钥内置，`desktop/src-tauri/src/updater.rs`），GitHub 账号被盗、Release 资产被换掉时不会安装。
- Android 依赖 APK 签名（系统拒绝签名不同的更新）。
- 浏览器扩展走商店更新。
- 依赖：只用审计过的密码学 crate（加密规格 §1）；Cargo.lock 固定版本；发版构建用 `--locked`。

## 6. 非目标

- 防御已解锁设备上的恶意软件、被篡改的操作系统或浏览器（§3.9）。
- 防御服务端的拒绝服务和数据删除：靠多副本、备份和离线导出恢复，而不是阻止。
- 隐藏元数据（条目数量、大小、修订时间、设备信息、IP）。
- 多用户之间的访问控制、共享保险库的成员管理（v1 单账户，预留未实现）。
- 恢复忘记的主密码（恢复码预留未实现）；同时丢失主密码和 Secret Key 时数据不可恢复，这是设计使然。
- 浏览器原生密码管理器、系统钥匙串里的密码；其他密码管理器的安全性。
