# NyaPassword 开发计划

> 配合 [设计方案.md](设计方案.md) 阅读（功能清单见 §1.1，已确认的决定见 §13）；界面见 [prototype.html](prototype.html)。每完成一项就在这里勾掉，并更新对应仓库的 README。

## 总体顺序

```
M0 立刻备份现有密码库 + 技术验证 + 规格定稿
M1 common 核心 + server（无界面，开发 CLI 驱动）         ← 数据安全的地基，验收最严
M2 共享界面 + desktop（Windows 实测；macOS / Linux 同时构建）+ 网页版 / 管理后台
M3 chrome 浏览器扩展（Chrome / Edge）
M4 android
M5 SSH agent、快捷搜索与自动输入、扩展 ↔ 桌面联动
   ── 双轨运行（与 Vaultwarden 并行 ≥ 4 周）→ 切换为主力 ──
之后：泄露检查、解锁方式（PIN、启动时生物识别、扩展由桌面端解锁；已实现，待实机验证）、自定义模板、Windows passkey 插件……（见文末）
```

先做没有界面的核心和服务端，是因为“密码不能乱”取决于加密、格式、同步、备份这四块；界面晚一点做不影响数据，而这四块后改代价很大。

不做：家庭共享（只预留）、Firefox、Android CXP 迁移、iOS、服务端非 Docker 部署（设计方案 §1）。

### M1 验收（全部通过才进 M2）
- [ ] 用你真实的 Vaultwarden 导出导入，逐条比对 **100% 一致**（含附件、passkey、自定义字段、密码历史）；导出 KDBX 后用 KeePassXC 打开抽查。
- [ ] 两个 CLI 客户端对同一批条目随机并发修改 / 离线修改 / 删除 10 万次（压测脚本），最终：无数据丢失（每个写入过的值都能在当前值、冲突或历史中找到）、两端和服务端摘要一致。<br>进展：服务端压测 4 个种子 × 5000 次、npw-dev 5 设备 × 1000 次均无丢失；10 万次尚未跑。
- [ ] 推送过程中随机 `kill -9` 服务端和客户端 1000 次：无损坏、无重复条目。<br>进展：npw-dev kill-test 每轮杀服务端 15–25 次无丢失；1000 次尚未跑。
- [ ] 备份到 OSS + WebDAV；删除服务器数据目录后用离线私钥恢复，客户端无感继续同步。<br>进展：fs 目标的“备份 → 删数据 → 离线私钥恢复 → 继续同步”已通过；真实 OSS / WebDAV 未测。
- [ ] 服务器拿着备份凭据删除 OSS 上的备份：失败。
- [ ] 加密样例在 Windows、Linux、macOS、WASM（node）、Android 目标上都能解开。

## M5 SSH 与桌面增强
- [x] ssh-agent（Windows 命名管道，被 Windows OpenSSH 服务 / 其他 agent 占用时报告占用者、可改管道名；macOS / Linux Unix socket，实验性），每次签名确认（可“锁定前都允许”），锁定时先提示解锁；Git SSH 签名（SSHSIG，rsa-sha2-512 / ed25519 / ecdsa 用真实 `ssh-keygen -Y sign/verify` 和 `git commit -S` 验证）；WSL 桥接说明（desktop README）。SSH 密钥条目的生成 / 导入 / 导出公钥界面另做。
- [x] 快捷搜索 + 自动输入：全局快捷键（默认 Ctrl+Shift+Alt+Space，可改；旧默认 Ctrl+Shift+Space 已保存的保持不变）、按前台窗口标题 / 进程名 / 网址匹配、拼音搜索、输入序列（`autofill.auto_type`）、复制用户名 / 密码 / 验证码；Windows `SendInput` + `KEYEVENTF_UNICODE`。macOS CGEvent、Linux X11 **未实现**（只能复制，界面会提示）。
- [x] 扩展 ↔ 桌面 Native Messaging：配对（双方显示同一 6 位数字、桌面确认）后桌面解锁则扩展可解锁，桌面锁定则已连接的扩展锁定；宿主注册（Windows HKCU，Chrome / Edge / Chromium；macOS / Linux 清单文件，实验性），关闭时和卸载时移除。
- [x] 导入：1Password（1PUX / CSV）、KeePass、Chrome CSV。
- [x] 条目“使用前需要验证”（`reprompt`，相当于 Bitwarden 的“主密码重新提示”，从 Bitwarden 导入时自动转换）：网页版 / 桌面端 / 扩展密码库页在验证前只显示标题、用户名和网址；扩展由 Service Worker 强制（内联菜单 / 提示框 / 弹窗里输入主密码，一次验证只放行这个条目一次，快捷键和页面加载时自动填写跳过）；桌面端快捷搜索验证后才自动输入 / 复制，SSH agent 每次签名都验证（Windows Hello 或主密码）；Android 详情页遮挡、自动填充数据集先认证。说明见威胁模型.md §3.8.1。（Windows Hello、Android 真机流程未实测）

## 贯穿始终的规则
1. **格式与 API 只增不改**；发版前冻结（release-lib 检查）。
